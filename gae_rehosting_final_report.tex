\title{Rehosting Berbasis Browser untuk Akses Lintas Sistem Operasi pada GAMA Animation Engine}

\author{

Dhimas Early Oceandy, Hammam Muhammad Yazid}

\maketitle

\begin{abstract}
GAMA Animation Engine (GAE), salah satu komponen dari proyek Gamatutor, merupakan aplikasi desktop native Windows yang digunakan untuk membuat dan menjalankan animasi tutorial sederhana. Aplikasi ini masih relevan untuk digunakan, tetapi bentuknya sebagai aplikasi Windows membatasi akses pengguna karena umumnya membutuhkan perangkat Windows dan instalasi lokal. Proyek ini menangani keterbatasan tersebut melalui pendekatan \textit{cloud rehosting}. Implementasi dilakukan dengan menjalankan GAE pada sebuah instans Windows EC2, lalu menyediakan akses berbasis browser melalui Apache Guacamole yang dipasang pada instans Linux EC2. Pengguna berinteraksi dengan GAE dari web browser, sedangkan Guacamole meneruskan sesi tersebut ke server Windows menggunakan Remote Desktop Protocol (RDP). Hasil implementasi menunjukkan bahwa GAE dapat diakses dari berbagai sistem operasi tanpa instalasi aplikasi di perangkat pengguna dan tanpa perubahan signifikan pada aplikasi asli. Dengan demikian, rehosting menjadi pendekatan yang cukup praktis ketika kebutuhan utama proyek adalah akses lintas sistem operasi, penggunaan melalui browser, dan kemudahan distribusi, bukan perancangan ulang aplikasi menjadi sepenuhnya \textit{cloud-native}.
\end{abstract}

\begin{IEEEkeywords}
komputasi awan, rehosting, aplikasi legacy, Apache Guacamole, AWS EC2, Remote Desktop Protocol, akses lintas sistem operasi, GAMA Animation Engine
\end{IEEEkeywords}

\section{Pendahuluan}

Banyak aplikasi yang masih berguna di lingkungan akademik maupun institusi tidak dirancang untuk pola penggunaan lintas perangkat seperti saat ini. Sebagian aplikasi tersebut dibuat sebagai aplikasi desktop native sehingga sangat bergantung pada sistem operasi tertentu. GAMA Animation Engine (GAE), bagian dari proyek Gamatutor, merupakan salah satu contohnya. Aplikasi ini menyediakan perangkat desktop seperti TutorialGenerator dan PlayerAnimasi untuk membuat serta menjalankan konten animasi tutorial.

Permasalahan utama dalam proyek ini adalah aksesibilitas. Pada model penggunaan awal, GAE paling mudah digunakan ketika pengguna memiliki lingkungan Windows yang sesuai dan dapat menyiapkan aplikasi secara lokal. Kondisi tersebut menyulitkan pengguna yang memakai macOS, Linux, Chromebook, atau perangkat lain yang tidak dapat menjalankan aplikasi desktop Windows secara langsung. Selain itu, distribusi aplikasi menjadi kurang praktis karena proses instalasi dan penyiapan harus diulang pada setiap perangkat pengguna.

Untuk menjawab masalah tersebut, proyek ini tetap mempertahankan GAE sebagai aplikasi desktop Windows, tetapi memindahkan lingkungan eksekusinya ke cloud. Pengguna tidak lagi perlu memasang aplikasi di perangkat lokal. Pengguna cukup membuka browser dan mengakses sesi Windows jarak jauh yang sudah memiliki GAE di dalamnya. Rancangan ini berfokus pada empat tujuan: akses lintas sistem operasi, penggunaan melalui browser, minim instalasi di sisi pengguna, dan tetap menjaga perilaku aplikasi asli.

Implementasi akhir menggunakan Apache Guacamole sebagai gerbang akses desktop jarak jauh berbasis browser dan Amazon Elastic Compute Cloud (EC2) sebagai infrastruktur cloud. Sebuah instans Linux EC2 menjalankan Guacamole sebagai gateway, sedangkan instans Windows EC2 menjalankan aplikasi GAE. Laporan ini membahas rancangan sistem, proses implementasi, hasil pengujian, keterbatasan, serta lampiran yang diperlukan untuk memenuhi ketentuan laporan akhir proyek cloud computing.

\section{Metode}

\subsection{Analisis Aplikasi dan Permasalahan}

GAE dianalisis sebagai aplikasi desktop native Windows. Berdasarkan proposal proyek dan karakteristik aplikasinya, GAE dibuat menggunakan Delphi/Object Pascal dengan Visual Component Library (VCL), berjalan sebagai aplikasi Windows mandiri, dan menggunakan aset lokal seperti berkas animasi, gambar, serta audio. Karakteristik tersebut membuat aplikasi bergantung pada lingkungan desktop Windows.

Masalah aksesnya dapat dirumuskan secara sederhana: pengguna membutuhkan sistem operasi dan konfigurasi lokal yang sesuai sebelum dapat memakai aplikasi. Dalam konteks kelas atau penggunaan bersama, hal ini kurang efisien karena setiap perangkat harus disiapkan satu per satu. Oleh karena itu, proyek membutuhkan model deployment yang tetap menyediakan runtime Windows, tetapi menyajikan aksesnya melalui antarmuka yang umum tersedia di berbagai perangkat. Browser dipilih sebagai antarmuka utama karena hampir semua sistem operasi modern memilikinya.

\subsection{Strategi Migrasi}

Strategi yang dipilih adalah rehosting, atau sering disebut \textit{lift-and-shift}. Rehosting memindahkan lingkungan eksekusi aplikasi ke infrastruktur cloud dengan perubahan seminimal mungkin pada aplikasi itu sendiri. Strategi ini sesuai karena proyek tidak bertujuan membangun ulang GAE menjadi aplikasi web. Tujuan utamanya adalah membuat aplikasi yang sudah ada menjadi lebih mudah diakses.

Pendekatan lain dinilai kurang sesuai dengan ruang lingkup proyek. Menulis ulang GAE sebagai aplikasi web akan membutuhkan perubahan pada antarmuka, model eksekusi, dan cara aplikasi menangani berkas lokal. Perancangan ulang menjadi aplikasi \textit{cloud-native} juga akan membutuhkan usaha pengembangan yang lebih besar dan berpotensi mengubah perilaku aplikasi asli. Rehosting lebih realistis karena tetap menjaga lingkungan desktop Windows, tetapi menambahkan lapisan akses cloud berbasis browser.

\subsection{Arsitektur Target}

Arsitektur sistem ditempatkan di dalam AWS VPC. Secara umum, arsitektur terdiri dari tiga lapisan: lapisan klien, lapisan gateway, dan lapisan target. Lapisan klien adalah perangkat pengguna dan web browser. Lapisan gateway berupa instans Linux EC2 yang membuka Apache Guacamole melalui HTTP port 8080 pada tahap prototipe dan SSH port 22 untuk administrasi. Di dalam instans Linux tersebut, Docker menjalankan layanan Guacamole, \texttt{guacd}, dan MySQL/MariaDB. Lapisan target berupa instans Windows EC2 yang menjalankan aplikasi desktop GAE dan menerima koneksi RDP hanya melalui jalur internal VPC dari gateway Guacamole.

\subsection{Prosedur Deployment}

Implementasi dilakukan dalam dua tahap. Tahap pertama adalah pembuktian konsep secara lokal menggunakan lingkungan Windows tervirtualisasi. Tahap kedua memindahkan arsitektur tersebut ke AWS.

Prosedur deployment cloud yang dilakukan adalah sebagai berikut:

\begin{enumerate}
    \item Mengatur AWS budget monitoring untuk mengurangi risiko biaya tidak terduga.
    \item Membuat komponen jaringan yang diperlukan, termasuk VPC, subnet, route table, dan internet gateway.
    \item Menjalankan instans Linux EC2 untuk Apache Guacamole.
    \item Menjalankan instans Windows EC2 untuk aplikasi GAE.
    \item Mengatur security group agar pengguna mengakses Guacamole melalui browser, sementara akses RDP ke Windows dibatasi ke jaringan internal atau gateway Guacamole.
    \item Memasang Docker dan Docker Compose pada instans Linux EC2.
    \item Mendeploy Guacamole, \texttt{guacd}, dan layanan database menggunakan repository deployment.
    \item Memasang atau menyalin artefak aplikasi GAE ke instans Windows EC2.
    \item Membuat entri koneksi RDP pada Guacamole yang mengarah ke instans Windows EC2.
    \item Menguji akses dari browser dan membandingkannya dengan pembuktian konsep lokal.
\end{enumerate}

\subsection{Repository}

Proyek ini menggunakan dua repository. Repository GAE/Gamatutor asli menyediakan artefak aplikasi dan materi sumber dari aplikasi yang direhosting \cite{gamatutor}. Repository deployment proyek berisi konfigurasi berbasis Docker untuk lapisan gateway Guacamole \cite{deployment-repo}. Pemisahan ini penting karena proyek tidak mengklaim membangun ulang GAE. Kontribusi utama proyek adalah menyiapkan lingkungan rehosting cloud agar aplikasi yang sudah ada dapat diakses melalui browser.

\section{Hasil}

\subsection{Pembuktian Konsep Lokal}

Milestone pertama adalah pembuktian konsep lokal menggunakan VirtualBox. Tim memasang GAE di dalam mesin virtual Windows lokal dan memverifikasi bahwa lingkungan tersebut dapat diakses melalui RDP. Pada tahap itu, integrasi Guacamole belum selesai dan progres dilaporkan sebesar 40\%. Hasil ini menunjukkan bahwa aplikasi dapat berjalan pada lingkungan Windows tervirtualisasi dan dapat dijangkau secara jarak jauh.

\subsection{Hasil Rehosting Cloud}

Deployment akhir berhasil merehosting GAE menggunakan arsitektur pada Gambar~\ref{fig:architecture}. Pengguna mengakses Guacamole dari browser. Guacamole kemudian membuka sesi RDP ke instans Windows EC2 tempat GAE dipasang. Tim melaporkan implementasi akhir sebagai 100\% selesai setelah alur akses berbasis browser berhasil diverifikasi.

Hasil tersebut memenuhi tujuan aksesibilitas utama. Pengguna tidak perlu memasang GAE pada perangkat lokal. Pengguna dari sistem operasi berbeda dapat mengakses lingkungan aplikasi yang sama melalui browser. Kebutuhan runtime Windows dipusatkan di cloud, sementara browser menjadi antarmuka utama di sisi pengguna.

\subsection{Pengujian Fungsional}

Pengujian fungsional difokuskan pada kelayakan akses dan operasi dasar. Tujuannya adalah memastikan bahwa aplikasi dapat dijangkau dan digunakan melalui lingkungan rehosting, bukan melakukan pengukuran performa secara rinci.

\subsection{Hasil Konfigurasi Deployment}

Repository deployment menggunakan Docker Compose untuk mendefinisikan lingkungan gateway Guacamole. Layanan utama yang digunakan adalah Guacamole, \texttt{guacd}, dan database MariaDB/MySQL. Pada tahap prototipe, Guacamole dibuka melalui port 8080. Layanan \texttt{guacd} menangani penerjemahan protokol menuju RDP, sedangkan database menyimpan konfigurasi pengguna dan koneksi.

Docker Compose membuat proses penyiapan gateway lebih konsisten karena layanan yang dibutuhkan dapat dijalankan bersama pada instans Linux EC2. Namun, konfigurasi prototipe juga menunjukkan beberapa aspek keamanan yang perlu diperbaiki, terutama terkait pengelolaan nilai akses dan berkas konfigurasi.

\subsection{Demonstrasi Video}

Deliverable akhir mensyaratkan dua video demonstrasi. Video pertama menunjukkan GAE pada lingkungan lokal atau on-premise. Video kedua menunjukkan GAE pada lingkungan cloud melalui akses browser menggunakan Apache Guacamole. URL video akhir perlu dimasukkan pada Lampiran~D sebelum pengumpulan.

\section{Diskusi}

\subsection{Peningkatan Aksesibilitas}

Kontribusi utama proyek ini bukan penambahan fitur baru pada aplikasi, melainkan model akses yang lebih mudah. Pada model awal, pengguna harus menyiapkan lingkungan Windows. Pada model rehosting, pengguna cukup menggunakan browser. Dengan demikian, kebutuhan pengguna berubah dari memasang aplikasi desktop Windows menjadi membuka browser dan masuk ke sesi yang sudah disediakan.

Pendekatan ini berguna untuk skenario lintas sistem operasi. Pengguna Windows, macOS, Linux, atau perangkat lain yang memiliki browser modern dapat mengakses lingkungan GAE yang sama. Dari sisi pemeliharaan, aplikasi juga cukup disiapkan pada instans Windows EC2, bukan dipasang berulang pada banyak perangkat lokal.

\subsection{Kesesuaian Strategi Rehosting}

Rehosting sesuai dengan ruang lingkup proyek karena masalah yang diselesaikan adalah aksesibilitas, bukan pengembangan ulang aplikasi. Menjaga GAE tetap berjalan di lingkungan Windows mempertahankan perilaku aplikasi asli. Menempatkan Guacamole di depan lingkungan tersebut membuat aplikasi dapat dijangkau melalui browser. Kombinasi ini menyelesaikan masalah proyek dengan kebutuhan infrastruktur yang masih terukur.

Perancangan ulang menjadi aplikasi \textit{cloud-native} akan membutuhkan ruang lingkup yang berbeda. Perubahan tersebut mencakup penulisan ulang antarmuka web, perancangan ulang mekanisme penyimpanan berkas, dan pembuatan arsitektur aplikasi baru. Pengembangan tersebut mungkin bernilai untuk jangka panjang, tetapi tidak diperlukan untuk membuktikan akses berbasis browser pada proyek ini.

\subsection{Pertimbangan Keamanan}

Akses desktop jarak jauh harus dikonfigurasi dengan hati-hati. Instans Windows EC2 tidak seharusnya membuka RDP langsung ke internet publik. Akses RDP perlu dibatasi hanya dari gateway Guacamole atau aturan jaringan privat. Antarmuka Guacamole juga sebaiknya menggunakan HTTPS pada lingkungan produksi, dan akses administratif perlu dibatasi hanya untuk pengguna yang berwenang.

Konfigurasi prototipe masih memiliki sejumlah penyederhanaan yang wajar untuk konteks kelas, tetapi belum layak dipakai langsung sebagai konfigurasi produksi. Deployment yang lebih kuat perlu menggunakan konfigurasi terpisah, aturan jaringan yang lebih ketat, serta akun Guacamole non-default.

\subsection{Keterbatasan Operasional}

Solusi ini masih bergantung pada instans Windows EC2. Artinya, sistem memiliki karakteristik operasional seperti lingkungan desktop jarak jauh, bukan aplikasi web ringan. Biaya, waktu aktif instans, lisensi Windows, stabilitas sesi, dan kualitas jaringan akan memengaruhi pengalaman pengguna.

Proyek ini juga berfokus pada kelayakan akses, bukan evaluasi performa mendalam. Belum ada pengukuran formal terhadap latensi, bandwidth, maupun pengujian banyak pengguna secara bersamaan. Pengujian tersebut perlu dilakukan jika sistem akan digunakan oleh banyak pengguna dalam kondisi yang lebih realistis.

\subsection{Pengembangan Lanjutan}

Beberapa perbaikan dapat membuat sistem lebih siap untuk digunakan di luar prototipe. HTTPS sebaiknya dikonfigurasi menggunakan domain dan sertifikat TLS. Autentikasi perlu menggunakan akun unik dan kebijakan akses yang lebih kuat. Akses RDP sebaiknya dibatasi menggunakan jaringan privat dan referensi security group. Cadangan juga perlu disiapkan untuk berkas animasi dan konfigurasi Guacamole. Selain itu, biaya cloud dapat ditekan dengan menghentikan instans saat tidak digunakan atau menjadwalkan waktu aktif berdasarkan kebutuhan kelas.

\section{Kesimpulan}

Proyek ini berhasil meningkatkan akses terhadap GAE dengan merehosting aplikasi native Windows tersebut ke lingkungan cloud. Implementasi menggunakan instans Linux EC2 yang menjalankan Apache Guacamole sebagai gateway berbasis browser dan instans Windows EC2 sebagai host aplikasi. Melalui arsitektur ini, pengguna dapat mengakses GAE dari berbagai sistem operasi tanpa memasang aplikasi secara lokal.

Hasil proyek menunjukkan bahwa rehosting merupakan strategi yang praktis ketika tujuan utama adalah membuat aplikasi desktop yang sudah ada menjadi lebih mudah dijangkau. Sistem ini tidak mengubah GAE menjadi aplikasi \textit{cloud-native}, tetapi berhasil memenuhi tujuan proyek: akses lintas sistem operasi, berbasis browser, tanpa instalasi lokal, dan tetap mempertahankan perilaku asli aplikasi Windows.

\section{Dokumentasi Langkah-Langkah Deployment}

Lampiran ini menjelaskan prosedur teknis rehosting yang digunakan dalam proyek. Nilai seperti alamat IP, nama key pair, username, dan password tidak dicantumkan secara eksplisit karena bersifat spesifik terhadap lingkungan deployment. Langkah-langkah berikut ditulis agar prosesnya dapat direplikasi dengan mengganti nilai placeholder sesuai konfigurasi masing-masing.

\subsection{Menyiapkan Budget dan Jaringan AWS}

Langkah awal adalah menyiapkan AWS Budget untuk memantau biaya selama eksperimen. Setelah itu, dibuat VPC untuk menempatkan Linux EC2 sebagai gateway dan Windows EC2 sebagai target aplikasi. VPC perlu memiliki subnet, route table, dan internet gateway agar Linux EC2 dapat diakses dari browser. Windows EC2 ditempatkan sebagai target privat yang hanya menerima koneksi RDP dari jalur internal atau dari gateway Guacamole.

Aturan jaringan yang digunakan pada prototipe dapat diringkas sebagai berikut:

\begin{itemize}
    \item Linux EC2 membuka akses HTTP port 8080 untuk antarmuka Guacamole pada tahap prototipe.
    \item Linux EC2 membuka SSH port 22 hanya untuk administrator atau jaringan tepercaya.
    \item Windows EC2 membuka RDP port 3389 hanya dari gateway Guacamole atau jaringan internal VPC.
    \item Windows EC2 tidak digunakan sebagai endpoint publik bagi pengguna akhir.
\end{itemize}

\subsection{Menjalankan Linux EC2 sebagai Gateway}

Instans Linux EC2 digunakan sebagai tempat menjalankan Apache Guacamole dan service pendukungnya. Sistem operasi yang digunakan adalah Ubuntu. Setelah instans berjalan, administrator masuk melalui SSH menggunakan key pair yang sudah dibuat pada AWS.

\begin{lstlisting}[style=code]
ssh -i <keypair.pem> ubuntu@<linux-ec2-public-ip>
\end{lstlisting}

Setelah berhasil masuk ke server, package index diperbarui dan dependensi dasar dipasang. Perintah yang digunakan dapat menyesuaikan versi sistem operasi, tetapi contoh berikut menggambarkan langkah yang digunakan pada lingkungan Ubuntu.

\begin{lstlisting}[style=code]
sudo apt update
sudo apt install -y docker.io docker-compose-v2 git
sudo systemctl enable docker
sudo systemctl start docker
sudo usermod -aG docker ubuntu
\end{lstlisting}

Setelah perintah tersebut dijalankan, sesi SSH dapat ditutup dan dibuka ulang agar perubahan grup Docker diterapkan pada user aktif.

\subsection{Mendeploy Guacamole dengan Repository Deployment}

Lapisan gateway dideploy menggunakan repository konfigurasi proyek. Repository ini berisi konfigurasi Docker Compose untuk menjalankan Apache Guacamole, \texttt{guacd}, dan database. Struktur minimal yang relevan pada repository deployment adalah sebagai berikut:

\begin{lstlisting}[style=code]
cloud-computing-final-project/
|-- Dockerfile
|-- docker-compose.yml
|-- init/
|-- data/
|-- drive/
`-- record/
\end{lstlisting}

Repository tersebut kemudian di-clone ke Linux EC2 dan dijalankan menggunakan Docker Compose.

\begin{lstlisting}[style=code]
git clone https://github.com/EarlyOcean/cloud-computing-final-project.git
cd cloud-computing-final-project
mkdir -p init data drive record
docker compose up -d
\end{lstlisting}

Status container diperiksa untuk memastikan semua service sudah berjalan.

\begin{lstlisting}[style=code]
docker compose ps
docker compose logs --tail=50
\end{lstlisting}

Jika service berjalan normal, antarmuka Guacamole dapat dibuka melalui browser menggunakan format URL berikut:

\begin{lstlisting}[style=code]
http://<linux-ec2-public-ip>:8080/guacamole/
\end{lstlisting}

Pada tahap prototipe, port 8080 digunakan secara langsung. Untuk penggunaan produksi, akses ini sebaiknya ditempatkan di belakang reverse proxy dan HTTPS.

\subsection{Menjalankan Windows EC2 untuk Aplikasi GAE}

Instans Windows Server EC2 digunakan sebagai host aplikasi GAE. Setelah instans dibuat, password administrator Windows diambil melalui AWS Console menggunakan key pair yang sesuai. Security group Windows EC2 dikonfigurasi agar RDP port 3389 tidak terbuka untuk seluruh internet, tetapi hanya dapat diakses dari gateway Guacamole atau jalur internal VPC.

Setelah desktop Windows dapat diakses, artefak aplikasi GAE diambil dari repository Gamatutor:

\begin{lstlisting}[style=code]
https://github.com/gamatutor/gamatutor
\end{lstlisting}

File aplikasi kemudian dipindahkan atau diunduh ke Windows EC2. Komponen yang diverifikasi adalah aplikasi TutorialGenerator dan PlayerAnimasi. Pada tahap ini, GAE tetap berjalan sebagai aplikasi desktop Windows biasa; perbedaannya adalah lingkungan eksekusinya berada pada server cloud.

\subsection{Membuat Koneksi RDP pada Apache Guacamole}

Setelah Guacamole dapat diakses, koneksi RDP baru dibuat dari halaman administrasi Guacamole. Parameter yang perlu diisi meliputi nama koneksi, protokol RDP, alamat privat Windows EC2, port 3389, serta kredensial Windows yang digunakan untuk login. Format konfigurasi koneksi dapat diringkas sebagai berikut:

\begin{lstlisting}[style=code]
Connection name : GAE Windows EC2
Protocol        : RDP
Hostname        : <windows-ec2-private-ip>
Port            : 3389
Username        : <windows-username>
Password        : <windows-password>
\end{lstlisting}

Setelah koneksi disimpan, pengguna memilih koneksi tersebut dari dashboard Guacamole. Jika konfigurasi berhasil, desktop Windows EC2 akan muncul langsung di browser. Dari sesi tersebut, pengguna dapat membuka TutorialGenerator atau PlayerAnimasi tanpa memasang GAE pada perangkat lokal.

\subsection{Validasi Akhir}

Validasi akhir dilakukan dengan memeriksa tiga hal. Pertama, pengguna dapat membuka halaman Guacamole melalui browser. Kedua, Guacamole berhasil membuat sesi RDP ke Windows EC2. Ketiga, GAE dapat dijalankan dari desktop Windows EC2 dan tetap dapat digunakan melalui sesi browser. Dengan validasi ini, tujuan utama proyek terpenuhi: aplikasi desktop Windows dapat digunakan secara lintas sistem operasi melalui browser tanpa instalasi lokal.
